# Метод «проверь дважды»

«Составь список, проверь его дважды. Если плохо — исправляй, пока не станет хорошо».

Главная мысль: тот, кто сделал работу, проверяет её с теми же слепыми пятнами, пробелами в знаниях и систематическими ошибками, с которыми её делал. Два независимых проверяющих, которые не видят ни друг друга, ни хода работы, ломают эту ловушку.

Это слой проверки **после** создания результата, а не способ его создавать.

## Когда применять

- результат будет опубликован, разослан или увидят клиенты, партнёры, команда;
- нужно соблюсти юридические, регуляторные или брендовые требования;
- важна точность содержания: инструкции, обучающие материалы, тексты для клиентов, коммерческие предложения;
- пакетная генерация (много карточек, описаний, ответов), где выборочный просмотр пропускает системные ошибки;
- высокий риск выдумки: утверждения, статистика, ссылки, цитаты, юридические формулировки.

**Не применять:** к внутренним черновикам, исследовательским заметкам и задачам, где проверка механическая (сумма в таблице сходится или нет, файл открывается или нет — для этого достаточно прямой проверки).

Подходит и для программного кода — тогда в чек-лист добавляются пункты про код (см. ниже).

## Что нужно на входе

1. **Постановка задачи** — что должно было получиться (бриф, ТЗ, запрос).
2. **Результат** — сам текст, документ, таблица, набор описаний.
3. **Чек-лист (рубрика)** — критерии с объективным условием «пройдено / не пройдено». Это самый важный вход: размытый чек-лист даёт размытую проверку.

## Шаги

### Фаза 1. Сделай (создание)
Выполни основную задачу как обычно. Метод ничего не меняет в том, как ты создаёшь результат.

### Фаза 2. Проверь дважды (две независимые проверки)
Запусти двух проверяющих — проверяющий Б и проверяющий В. Лучше всего — два отдельных чата или две отдельные роли, которые не видят черновиков, обсуждения и мнения друг друга. Обязательные условия:

1. **Изоляция** — ни один не видит оценку другого;
2. **Одинаковый чек-лист** — оба получают одни и те же критерии;
3. **Одинаковые входные** — оба получают и постановку, и результат;
4. **Структурированный ответ** — каждый возвращает вердикт по пунктам, а не свободный текст.

Задание для проверяющего:

```text
Ты — независимый проверяющий. Ты НЕ видел никаких других проверок этого результата.

## Постановка задачи
{постановка}

## Результат на проверку
{результат}

## Чек-лист
{критерии}

## Инструкция
Оцени результат по КАЖДОМУ критерию:
- ПРОЙДЕНО: критерий полностью выполнен, проблем нет
- НЕ ПРОЙДЕНО: найдена конкретная проблема (процитируй, что именно не так)

Ответ:
Вердикт: ПРОЙДЕНО / НЕ ПРОЙДЕНО
Проверки: [критерий — результат — подробность]
Блокирующие проблемы: [то, что обязательно исправить]
Пожелания: [необязательные улучшения]

Будь строгим. Твоя задача — найти проблемы, а не одобрить.
```

Если отдельных чатов нет (запасной вариант): сделай проверку последовательно, явно «обнуляя» контекст — «Ты проверяющий 1. Оцени ТОЛЬКО по чек-листу. Ищи проблемы», запиши находки дословно; затем заново: «Ты проверяющий 2…». Этот вариант слабее — есть риск, что первая проверка «просочится» во вторую.

### Фаза 3. Хорошо или плохо (ворота)
- Б прошёл **и** В прошёл → **ХОРОШО**, можно выпускать (публикация или отправка — только после явного подтверждения пользователя).
- Иначе → **ПЛОХО**: собери блокирующие проблемы обоих, убери дубли, отдельно собери пожелания.

Почему должны пройти оба: если проблему заметил хотя бы один — она реальна. Слепое пятно второго — ровно то, ради чего метод существует.

### Фаза 4. Исправляй, пока не станет хорошо (цикл)
1. Исправь **только** отмеченные блокирующие проблемы. Без переделок и улучшений, о которых не просили. Пожелания — по желанию.
2. Запусти **обоих** проверяющих заново на исправленном результате — **новыми** (новые чаты/роли без памяти о прошлом круге), иначе прошлый круг создаёт якорь.
3. Повторяй. Максимум **3 круга**. Если после 3-го круга всё ещё «плохо» — остановись и передай человеку: результат + список нерешённых проблем.

## Чек-лист: базовые критерии

| Критерий | Условие «пройдено» | Признак провала |
| --- | --- | --- |
| Фактическая точность | Все утверждения проверяемы по источнику или общеизвестны | Выдуманная статистика, неверные даты, несуществующие документы |
| Без выдумок | Нет выдуманных компаний, цитат, ссылок, источников | Ссылки на несуществующие страницы, цитаты без источника |
| Полнота | Каждое требование из постановки выполнено | Пропущенные разделы, неучтённые случаи |
| Соответствие правилам | Все ограничения проекта соблюдены | Запрещённые слова, нарушение тона, несоответствие законодательству |
| Внутренняя согласованность | Нет противоречий внутри результата | В разделе А сказано Х, в разделе Б — не-Х |
| Техническая корректность | Расчёты и формулы верны; для кода — запускается, логика верна | Ошибка в арифметике, неверная формула, ошибки в коде |

**Дополнения по направлениям:**
- *Контент и маркетинг:* соответствие голосу бренда; требования SEO (ключевые слова, заголовки, мета-описания, структура); нет неправомерного использования чужих товарных знаков; призыв к действию есть и ссылка ведёт куда нужно.
- *Чувствительное к законам (юридическое, финансовое, регулируемое):* нет гарантий результата и необоснованных обещаний; обязательные оговорки на месте; только одобренная терминология; формулировки соответствуют юрисдикции.
- *Если проверяется код:* обработка ошибок, безопасность (нет секретов в коде, проверка входных данных), покрытие новых веток тестами, аккуратная работа с пустыми значениями.

## Большие пакеты (100+ единиц)

Полная двойная проверка каждой единицы слишком дорога. Используй выборку:
1. Проверь методом случайную выборку — 10–15% пакета, минимум 5 единиц.
2. Разложи найденные провалы по типам (выдумка, полнота, соответствие правилам и т.д.).
3. Если виден системный паттерн — исправь его во **всём** пакете.
4. Сделай новую выборку и проверь исправленный пакет.
5. Повторяй, пока чистая выборка не пройдёт.

## Что на выходе

- Итоговый вердикт: ХОРОШО (сколько кругов понадобилось) или ПЕРЕДАНО ЧЕЛОВЕКУ.
- Таблица по каждому кругу: критерий — Б — В — что исправлено.
- Если передано человеку: последний вариант результата + список нерешённых блокирующих проблем.
- Отдельно: необязательные пожелания, которые не вносились.

## Проверка перед сдачей

- Чек-лист состоит из объективных критериев «да/нет», а не вкусовых?
- Проверяющие действительно не видели друг друга и черновиков?
- В каждом новом круге — новые проверяющие без памяти о прошлом?
- Исправлены только отмеченные проблемы, без лишних переделок?
- Число кругов не больше 3?
- Публикация / отправка — только после явного подтверждения пользователя?

## Частые ошибки и защита

| Ошибка | Признак | Защита |
| --- | --- | --- |
| Бесконечный цикл | После исправлений находятся всё новые проблемы | Лимит 3 круга, затем к человеку |
| «Штамповка» | Оба проверяющих пропускают всё | Жёсткая установка: «твоя задача — найти проблемы, а не одобрить» |
| Уход во вкусовщину | Проверяющие отмечают стиль, а не ошибки | Узкий чек-лист только с объективными критериями |
| Регресс при исправлении | Исправили А — сломали Б | Новые проверяющие каждый круг ловят регресс |
| Общее слепое пятно | Оба пропустили одно и то же | Независимость снижает риск, но не убирает; для критичного — третий проверяющий или выборочная проверка человеком |
| Взрыв затрат | Много кругов на больших результатах | Выборка для пакетов, лимит на проверку |

## Как понять, что метод работает

- **Доля прохождения с первого круга** — цель больше 70%;
- **Среднее число кругов до «хорошо»** — цель меньше 1,5;
- **Типы провалов** — распределение: выдумки / полнота / соответствие правилам;
- **Согласие проверяющих** — какая доля проблем найдена обоими, а какая одним (низкое согласие = чек-лист надо уточнить);
- **Утечки** — ошибки, найденные после выпуска, которые метод должен был поймать (цель — 0).

Цена: одна проверка обходится примерно в 2–3 раза дороже самого создания результата. Для важных материалов это дёшево по сравнению с ценой ошибки на публике (репутация, исправления, потеря доверия). Выборка для пакетов снижает затраты примерно до 15–20% от полной проверки.

# SEO: аудит и улучшение видимости сайта в поиске

Цель — чтобы сайт находили в поиске за счёт технической исправности, скорости и релевантного содержания, а не за счёт трюков.

## Когда применять

- проверить, может ли поисковик обойти и проиндексировать сайт: robots.txt, запрет индексации (noindex), канонические адреса (canonical), редиректы;
- улучшить заголовки страниц (title), описания (meta description) и структуру подзаголовков;
- добавить или проверить структурированные данные (разметку schema.org);
- ускорить загрузку страниц (показатели Core Web Vitals);
- подобрать ключевые слова и распределить их по страницам;
- спланировать внутренние ссылки, карту сайта (sitemap) или правила robots.txt.

## Что нужно на входе

- адрес сайта и список важных страниц (главная, меню/каталог, страницы точек, франшиза, блог);
- доступ к самим страницам: если у агента есть доступ в интернет — открыть их; если нет — попросить пользователя прислать текст страниц, title/description, robots.txt, sitemap, отчёты из инструментов веб-мастера (Яндекс Вебмастер, Google Search Console) и замеры скорости (например, PageSpeed Insights);
- цель: какие запросы важны бизнесу (например, «доставка шаурмы рядом», «франшиза общепита»), регион, кто клиент.

## Шаги

### 0. Принципы (держать в голове на всех шагах)

1. Сначала устранить технические блокеры, потом оптимизировать контент.
2. Одна страница — одно ясное поисковое намерение (что человек хочет найти).
3. Долгосрочные сигналы качества важнее манипуляций.
4. Думать «сначала мобильная версия» — поисковики индексируют мобильную версию.
5. Каждая рекомендация — про конкретную страницу и выполнима.

### 1. Технический чек-лист

**Обход (crawlability):**
- robots.txt открывает важные страницы и закрывает малоценные (служебные, фильтры, корзина);
- ни одна важная страница не закрыта noindex случайно;
- важные страницы доступны в несколько кликов от главной;
- нет цепочек редиректов длиннее двух переходов;
- канонические адреса согласованы и не зациклены.

**Индексация:**
- единый формат адресов (с/без www, со слешем/без);
- если есть языковые версии — правильно указан hreflang;
- sitemap содержит именно те страницы, которые должны быть в поиске;
- нет дублей страниц, конкурирующих друг с другом без указания канонической.

**Скорость (Core Web Vitals):**
- LCP (время отрисовки главного элемента) < 2,5 с;
- INP (отклик на действие) < 200 мс;
- CLS (сдвиги вёрстки при загрузке) < 0,1;
- типовые исправления: заранее загружать главную картинку, убрать блокирующие отрисовку скрипты/стили, резервировать место под элементы, облегчить тяжёлый JavaScript.

**Структурированные данные (разметка):**
- главная — Organization или LocalBusiness/Restaurant, где уместно;
- статьи и новости — Article / BlogPosting;
- товары/блюда с ценой — Product и Offer;
- внутренние страницы — BreadcrumbList («хлебные крошки»);
- блок вопросов-ответов — FAQPage, только если на странице действительно есть такие вопросы и ответы.

### 2. Правила для страниц

**Title (заголовок страницы в выдаче):**
- примерно 50–60 символов;
- главное ключевое слово/тема ближе к началу;
- читается человеком, а не набит словами для роботов.

Формула: `Главная тема — уточнение | Бренд`
Пример: `Шаурма с доставкой — в центре города за 30 минут | Название сети`

**Meta description (описание под заголовком в выдаче):**
- примерно 120–160 символов;
- честно описывает страницу;
- тема страницы входит естественно.

Формула: `Действие + тема + ценность + одна подтверждающая деталь`.

**Подзаголовки:**
- один ясный H1;
- H2 и H3 отражают реальную структуру содержания;
- не нарушать иерархию ради внешнего вида.

### 3. Подбор и распределение ключевых слов

1. Определить поисковое намерение (что ищет человек: купить, узнать, найти рядом).
2. Собрать реалистичные варианты запросов (если есть доступ к сервисам статистики запросов — использовать; если нет — попросить пользователя выгрузку).
3. Приоритизировать по совпадению с намерением, ценности для бизнеса и конкуренции.
4. Закрепить одну главную тему/ключ за одним адресом.
5. Найти и устранить «каннибализацию» — когда несколько страниц претендуют на один запрос.

### 4. Внутренние ссылки

- ставить ссылки с сильных страниц на те, которые нужно продвинуть;
- текст ссылки описательный («меню завтраков»), а не «здесь» или «подробнее», если можно точнее;
- с новых страниц ставить ссылки на подходящие существующие и наоборот.

### 5. Применение изменений

Агент готовит рекомендации и готовые тексты/код разметки. Любые изменения на живом сайте, публикация, отправка карты сайта в поисковики — **только после явного подтверждения пользователя**.

## Что на выходе

Список находок по приоритету, каждая в формате:

```
[ВЫСОКИЙ] Одинаковые title на страницах блюд
Где: страницы меню /menu/<блюдо>
Проблема: все страницы получают один шаблонный заголовок — поисковик не различает их, сигналы дублируются.
Исправление: формировать уникальный title из названия блюда и категории.
```

Уровни: ВЫСОКИЙ / СРЕДНИЙ / НИЗКИЙ. Плюс, если нужно: таблица «ключевая тема → адрес страницы», готовые варианты title/description, пример разметки.

Пример разметки (JSON-LD) для статьи:

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Заголовок страницы",
  "author": { "@type": "Person", "name": "Имя автора" },
  "publisher": { "@type": "Organization", "name": "Название бренда" }
}
```

## Проверка перед сдачей

- каждая рекомендация привязана к конкретной странице или файлу;
- выводы сделаны по реальной странице, а не по догадке;
- технические блокеры стоят выше контентных правок;
- разметка соответствует тому, что реально есть на странице;
- длины title/description в рекомендованных пределах;
- нет советов, требующих необратимых действий без подтверждения пользователя.

## Частые ошибки

| Ошибка | Как правильно |
|---|---|
| Переспам ключевыми словами | писать сначала для людей |
| Тонкие почти одинаковые страницы | объединить или сделать действительно разными |
| Разметка для содержимого, которого нет на странице | разметка = реальность |
| Советы по контенту без просмотра страницы | сначала прочитать реальную страницу |
| Общие советы «улучшите SEO» | каждую рекомендацию — к странице или элементу |
